## Goal

Train two YOLO26s models on Roboflow datasets containing 164 traffic/street sign classes:
1. **Detection model** — finds signs in full street photos (bounding boxes)
2. **Classification model** — identifies sign type from a cropped sign image

Both models should use AdamW + cosine LR scheduler + early stopping, and save weights + metrics to the `runs/` folder.

## Outstanding Issues

### 1. Detector — Low mAP (14.5%)
- Both completed runs produced identical metrics, suggesting the GPU run may have actually used CPU
- **Check:** Verify `DEVICE=0` is set in the config cell AND the kernel is Python 3.12 before retraining
- Small dataset (3,064 images / 164 classes ≈ 19 per class) is a hard problem — metrics may be inherently limited

### 2. Classifier — Not converging (0.16% top-1 accuracy)
- After correct dataset conversion, training ran but accuracy stayed near 0
- 0.16% is worse than random (random = 1/164 ≈ 0.6%) — something is still wrong
- **Possible causes to investigate:**
  - The conversion script (`convert_to_cls_folder.py`) may have created wrong class→folder mapping — verify a few samples
  - `yolo26s-cls.pt` may not exist as a real model — ultralytics might have silently fallen back to a random init or wrong architecture. Try `yolo11s-cls.pt` instead
  - LR or batch size may need tuning for 164 classes

### 3. Roboflow SDK download broken
- Roboflow Python SDK silently fails to save files when the download path contains accented characters (`4. félév`)
- **Workaround in place:** Always manually download datasets as zip from the Roboflow website and extract locally, then set `DATA_YAML` or `DATASET_DIR` in the notebook config
